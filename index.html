SkillShikshya Central CRM · Onboarding task

Ship the Calls module

Build the Calls page so branch managers can see, search and export every call their counselors make. Along the way, fix a bug that charges counselors the wrong number of minutes.

Timebox
1 working day (~8 h)
Repos
Backend (Django) + Frontend (React)
AI tools
Allowed and encouraged
Output
A PR from your fork to each repo

Requirement in brief

Today: every phone call a counselor makes to a lead is saved, and its length is deducted from that counselor's prepaid call minutes. You can only see calls one lead at a time, and the Calls menu item opens a “Coming soon” screen.

We need: a working Calls page that:

  • shows how much calling the team did (count, talk time, who called most)
  • lists every call, with search and filters
  • opens the full details of one call
  • exports the filtered calls to a spreadsheet
  • only shows a user the calls from their own branch

Also fix: when a counselor types a call duration like 4.19 or 4:19, it's saved wrongly.

Already done for you: the backend endpoint GET /api/calls/ returns the call list with filters and search. You'll build the rest on top of it.

User stories

Do the stories marked Must first. Each story has a goal, acceptance criteria to check against, and build notes you can expand. Treat the build notes as guidance: if you find a better way that still meets the criteria, take it and explain why in your PR.

US-1

See the team's call activity at a glance

MustBE + FE

As a branch manager, I want totals at the top of the Calls page, so that I know how much calling my team did without counting rows.

Acceptance criteria

  • Four cards show Total calls (with the inbound/outbound split), Talk time, Average duration and Connect rate. A call counts as connected when it lasted more than 0 seconds.
  • A small chart shows calls per day, and a list shows the top 10 callers by number of calls.
  • Every number updates when the filters from US-2 change. For the same filters, Total calls equals the table's row count.
  • Days are counted in Nepal time. A call at 11 pm NPT belongs to that day, not the next one.
  • With no matching calls, the cards show 0 and the charts show an empty state. The page doesn't break.
Build notes

Backend: add GET /api/calls/summary/ as an @action(detail=False) on GlobalCallViewSet. Run it through self.filter_queryset(self.get_queryset()) so the filters, search and branch scoping are the same as the list's. Return one unpaginated object:

{
  "total_calls": 128, "inbound": 40, "outbound": 88,
  "total_seconds": 30215, "total_formatted": "08:23:35",
  "avg_seconds": 236, "connected_calls": 110, "connect_rate": 0.859,
  "by_day":  [{ "date": "2026-10-28", "calls": 14, "seconds": 3310 }],
  "by_user": [{ "user_id": 9, "name": "Shikhar", "calls": 40, "seconds": 9800 }]
}
  • Do all the arithmetic in the database with aggregate, annotate and Count(filter=Q(...)), not in a Python loop.
  • The server's TIME_ZONE is 'UTC', so pass tzinfo=ZoneInfo("Asia/Kathmandu") to TruncDate.
  • Calls without a created_by appear in by_user as user_id: null, name: "Unknown".

Frontend: use the useCallSummary(params) hook. Draw the charts with MiniBars and HBarList from src/components/charts.tsx; don't add a chart library. Show skeletons while loading.

Tests: correct totals, average and connect rate on a fixture that includes a 0-second call. A call at 20:00 UTC on Oct 28 counts under 2026-10-29. An empty result returns zeros.

US-2

Find specific calls

MustFE (+ small BE)

As a branch manager, I want to search and filter the call log, so that I can answer questions like “show me every outbound call Sita made yesterday”.

Acceptance criteria

  • /calls shows a table, newest first. Columns: When · Direction · Lead (name + reference) · Phone · Logged by · Duration (MM:SS) · Outcome · Recording.
  • Clicking the lead name opens that lead's detail page. The recording column shows a link only when the call has a recording.
  • Filters: search (lead, phone, caller, notes), direction, logged by (user picker), and date range with the presets Today, Last 7 days, This month and Custom. Staff users also get a branch filter. A Clear filters button resets everything.
  • Clicking the When or Duration header sorts by that column. Clicking again reverses the order, and an arrow shows the current direction.
  • The table pages through 20 rows at a time and says “Showing 21–40 of 128”.
  • Filters, sort and page are kept in the URL, so reloading or sharing the link shows exactly the same view. Changing a filter goes back to page 1.
  • A date range of “Today” includes calls up to 23:59:59. No calls from the last day are lost.
  • There are different messages for “no calls yet” and “no calls match these filters”, and an error message with a Retry button.
  • At 390 px wide, the page doesn't scroll sideways: the table scrolls inside its own box and the filters wrap. It's readable in light and dark mode.
Build notes
  • Replace the ComingSoonPage route for /calls in src/App.tsx with src/pages/calls/index.tsx. Copy the header layout from src/pages/payments/index.tsx.
  • Create src/types/calls.ts, src/services/calls.service.ts and src/hooks/use-calls.ts, using the same patterns as use-call-minutes.ts (keepPreviousData, query keys that start with ["calls", …]). Don't use any.
  • Keep filter state in useSearchParams. Debounce the search with useDebouncedValue.
  • Send dates to call_timestamp__gte and __lte as ISO strings with a timezone offset, using the start and end of the local day.
  • Sorting uses the existing ordering parameter (-call_timestamp, duration_seconds, and so on).
  • Small backend change: add a read-only duration_formatted field to GlobalCallSerializer using format_duration from apps/callminutes/utils.py, so the frontend doesn't have to format seconds.
US-3

Read the full details of one call

ShouldFE

As a branch manager, I want to open a call from the list, so that I can read the counselor's notes and what happens next.

Acceptance criteria

  • Clicking a row opens a side panel without leaving the page.
  • The panel shows the full date and time, direction, lead, phone, caller, logged by, duration, outcome, notes, next action, next follow-up, and the recording link if there is one.
  • Empty fields show “—” and are not hidden, so the layout stays the same from call to call.
  • The panel closes with Esc or the close button, and the list keeps its filters and scroll position.
Build notes

Use the existing Sheet component from src/components/ui/sheet.tsx. src/pages/students/student-detail-sheet.tsx is a good example to follow. The list response already has every field you need, so you don't need another API call.

US-4

Export calls to a spreadsheet

MustBE + FE

As a branch manager, I want to download the calls I'm looking at as a CSV, so that I can share them in reports and check them in Excel.

Acceptance criteria

  • An Export CSV button downloads all calls that match the current filters, across every page. It shows a spinner while the file is being prepared.
  • The file is named calls-YYYY-MM-DD.csv, with these columns in order: Date & time (NPT) · Direction · Lead · Reference · Phone · Caller · Logged by · Duration (MM:SS) · Seconds · Outcome · Notes · Recording.
  • The file opens in Excel and Google Sheets with Nepali (Devanagari) names displayed correctly.
  • A note that starts with =, +, - or @ is shown as plain text. It never runs as a spreadsheet formula.
  • Exporting 20,000 calls doesn't time out or run one database query per row.
Build notes
  • Backend: add GET /api/calls/export/ as an @action on GlobalCallViewSet, with the same filter_queryset call as the list. Use LeadViewSet.export_csv as a model. Use select_related and .iterator(). StreamingHttpResponse earns extra credit.
  • Write a UTF-8 BOM (﻿) first, so Excel reads Devanagari correctly.
  • Prefix any text cell that starts with = + - @ with '.
  • Frontend: fetch the file with axios and responseType: "blob", then save it with an object URL. A plain link won't work, because it skips the login-cookie refresh in src/lib/api.ts.
  • Tests: content type, header row, row count, respects filters, and neutralises a note that starts with =HYPERLINK(.
US-5

Log a call with the duration I actually typed

MustFE (bug fix)

As a counselor, I want the call duration I type to be saved exactly, so that I'm charged the right number of call minutes.

The bug: the Log Call dialog multiplies what you type by 60. So 4.5 is saved as 4 min 30 s, but everywhere else in the system 4.5 means 4 min 05 s. Typing 4:19 sends NaN.

Acceptance criteria

  • Typing 4:19, 4.19, 4m19s or 259 all save a 259-second call.
  • The field shows the hint MM:SS, e.g. 4:19 and a live preview under it, such as “= 4 min 19 sec”. Overflow carries over: 7:89 shows “= 8 min 29 sec”.
  • An invalid duration, or “Insufficient call minutes”, appears as an error on the field itself, not only as a pop-up.
  • After saving, the confirmation message shows the counselor's remaining balance, and the Calls page and call-minutes balance refresh.
Build notes
  • The bug is in src/pages/leads/components/lead-action-dialogs.tsx, on the line that builds duration_seconds: … Number(call.duration) * 60.
  • Send the raw text as duration_input. The backend already parses it; see “Flexible duration input” in apps/app_documents/lead_app_calls_api_guide.md.
  • For the preview, write a small TypeScript parser that mirrors parse_duration_to_seconds in apps/callminutes/utils.py. The backend's tests in apps/callminutes/tests.py are your spec.
  • The success response includes remaining_seconds. Invalidate the ["calls"] and ["call-minutes"] queries.
US-6

Branches only see their own calls

MustBE (tests + review)

As the business owner, I want each branch's call data to stay inside that branch, so that a counselor in Dharan can't see Biratnagar's leads and phone numbers.

Acceptance criteria

  • A non-staff user in branch X never sees branch Y's calls in the list, the summary (US-1) or the export (US-4). A backend test proves each case.
  • Staff users see all branches by default and can narrow to one with ?branch_id=.
  • Your write-up answers this: what does a non-staff user with no branch assigned see today? Describe the behaviour, the risk and your proposed fix. Don't change the behaviour in this PR.
Build notes

Scoping happens in BranchFilterBackend (apps/global_config/filters.py). If your summary and export go through filter_queryset, they get scoping automatically. The tests prove it. test_branch_scoping_for_non_staff in GlobalCallListTests shows how to set it up.

Small cleanup on the way: apps/lead/urls.py imports GlobalCallViewSet twice. Remove the duplicate. Document the two new endpoints in apps/app_documents/lead_app_calls_api_guide.md, in the style of the existing sections.

Setup

Both repositories are public. Start by forking each one to your own GitHub account using the Fork button on GitHub. Then clone your forks, not the originals:

  • github.com/vrittech/skillshikshya-central-crm-be
  • github.com/vrittech/skillshikshya-central-crm-fe
git clone https://github.com/<your-username>/skillshikshya-central-crm-be
git clone https://github.com/<your-username>/skillshikshya-central-crm-fe

# in each repo, create your working branch
cd skillshikshya-central-crm-be && git checkout -b feat/calls-summary-export
cd ../skillshikshya-central-crm-fe && git checkout -b feat/calls-page

Backend (port 8188)

cd skillshikshya-central-crm-be
cp .env.example .env
docker compose up --build -d
docker exec skillshikshyacrm_web python manage.py migrate
docker exec -it skillshikshyacrm_web python manage.py createsuperuser
docker exec skillshikshyacrm_web python manage.py test   # should be green before you start

Frontend (port 5173)

cd skillshikshya-central-crm-fe
npm install
npm run dev          # Vite proxies /api to localhost:8188
npm run seed:backend # optional: fills the backend with sample data

Log in with your superuser. Give yourself call minutes in Users → Call minutes, then open a few leads and use Log Call so you have data to work with.

Before writing code, spend 30–45 minutes reading apps/app_documents/lead_app_calls_api_guide.md and one finished frontend page such as src/pages/payments/. Most of this task is following patterns that already exist.

How to submit

In short: push your work to a branch on your fork, then raise a pull request from that branch into our repository (vrittech/skillshikshya-central-crm-be and vrittech/skillshikshya-central-crm-fe). Open one pull request per repository, then submit both PR URLs through the submission form sent to your email.

Pull requests are the only accepted way to submit. We won't review zip files, email attachments or direct links to branches.

1. Push your branches to your forks

git push -u origin feat/calls-summary-export   # backend fork
git push -u origin feat/calls-page             # frontend fork

Use small, focused commits in the repository's existing style (feat:, fix:, test:, docs:).

2. Open a pull request in each repository

On GitHub, open Compare & pull request from your fork's branch into vrittech/<repo> on main. Tick Allow edits by maintainers.

RepositoryYour branchPR title
skillshikshya-central-crm-befeat/calls-summary-export[Task] <Your Name> – Calls summary, export and branch scoping
skillshikshya-central-crm-fefeat/calls-page[Task] <Your Name> – Calls page and Log Call duration fix

3. Complete the PR descriptions

Both PRs should include:

  • A link to the other PR.
  • The user stories this PR covers (for example, US-1, US-4, US-6).
  • Steps a reviewer can follow to test your changes locally.

The frontend PR should also include:

  • Screenshots in light mode, dark mode and at phone width.
  • A short screen recording (under 2 minutes) showing filtering, sorting and exporting.
  • A write-up of no more than one page that covers:
    • which stories you finished, and which you cut or simplified, and why
    • your answer to the US-6 question
    • one thing in the codebase you would improve next, and why
    • how you used AI: what it produced, what you corrected, and one suggestion you rejected

4. Submit the form

Once both pull requests are open, check your email for the task submission link. Fill in the form at that link and paste the URLs of both pull requests, for example:

https://github.com/vrittech/skillshikshya-central-crm-be/pull/<number>
https://github.com/vrittech/skillshikshya-central-crm-fe/pull/<number>

Your submission is complete only when the form has been submitted before the agreed deadline. If you can't find the email, check your spam folder, then reply to the message that brought you this task.

Please note: your pull requests are for review only and will not be merged. Keep your forks and branches available until you hear back from us, and don't push changes after the deadline unless a reviewer asks you to. Never commit .env files, credentials or real customer data.

Using AI

  • You own every line. In review we'll ask you to explain parts of your code. “The AI wrote it” isn't an answer.
  • Show it the existing patterns, such as the Payments page, use-call-minutes.ts and GlobalCallListTests, so its output matches the codebase.
  • Check the tricky parts yourself: the Nepal-time day buckets, the end-of-day date filter, branch scoping and CSV escaping.
  • No secrets or real customer data (such as .env values or phone numbers) in prompts.
